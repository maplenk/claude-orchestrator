Harness Control

A Claude Code plugin that plans, delegates and verifies — where roles and harnesses are independent axes, and the tool was built by running itself.

36 commits32 files88 tests 4 harnesses3 rolesone eveningMIT

The premise

Two ideas carry the whole design.

Roles and harnesses are orthogonal. A role is the job — developer, ui-developer, verifier. A harness is the model executing it — claude, codex, grok, pi. One role definition runs on any of them, so a second opinion is genuinely comparable rather than four vendors' agents each doing things their own way.

The no-implement rule is enforced, not requested. In orchestrator mode a PreToolUse hook blocks source edits in the main session, so work reaches the tree only through an agent whose output was independently checked. The rule survives a long session because it lives in the system prompt and in a hook, not in a message that decays.

It started as a 274-line markdown file describing an orchestrator persona. The question was how to package it. The answer turned out to be: not as one thing.

How it was built

Five waves, each delegated and verified before the next. The tool ran itself from wave 1 onward.

  1. Packaging

    Split into output style, skill, agents and hook; packaged as a plugin with its own marketplace. Established that enforcement had to be a hook because skill-scoped restrictions clear on the next message.

  2. Data foundation — two tasks, concurrent, in worktrees

    A run registry in the bus: open, stage, pause, resume, close, persisted per channel. And run-role restructured from exec to a child process so a PID exists for the bus to signal, with exit codes propagated faithfully and INT/TERM closing the run rather than orphaning it.

  3. The ink shell

    A design arrived as a canvas mockup. Translated to vanilla JS against the live API — sidebar, wave flow, balance enso, harness garden, traffic feed. Every figure traces to a real field; the success rate reads 9 of 62 rather than a fabricated percentage, and nav entries with no backing data say NOT YET.

  4. Polish

    Explicit theme control, a painted SVG enso replacing a CSS border arc, the Mincho wordmark, per-harness marks, and a fix for failure rendering in the success colour. The washes were stretched so they read as paper rather than corner stickers.

  5. Verification

    Test coverage for the run registry — 61 checks to 88 — proving pause by freezing a real child process and watching its output stop. Independent verification runs on codex, deliberately not the harness that wrote the code.

The bug ledger

The most useful output of the evening. Every one was found by running the thing, not by reasoning about it — and the majority were in my own code.

Amber entries are bugs I wrote. Red are bugs an agent found or that shipped in someone else's code.

found by the dashboard, in my code

Enforcement was silently off for every user

Plugin output styles are stored namespaced — orchestrator:Orchestrator. The guard compared against the bare name, never matched, and returned early. Installing as a plugin is the only supported path, so the plugin's central safety property did nothing.

The doctor had the identical blind spot: it reported the style as unset while its guard self-test passed, because the guard was correctly doing nothing for a style it did not recognise. A self-test that shares the blind spot of the thing it tests is not a test.

exposed by fixing the previous one

Fixing the guard broke delegation

The guard exempted subagents via agent_id. A run-role harness is a top-level session and has none — indistinguishable from an orchestrator. The moment the style matched, every delegated write was denied. A wave died after 25 minutes having written nothing.

Delegation had only ever worked because the guard was broken. Wave 1a reported "File Edit/Write tools were blocked" and I attributed it to something else and moved on.

found by studying Intent

Read-only was a bluff on two of three harnesses

--read-only was accepted and enforced nothing on codex and grok. Verified by trying to breach each: pi's --tools read removes the tools and holds; codex's sandbox governs shell commands but not its own patch tool; grok's tool denylist leaves other paths open. Both overwrote the target file.

It now refuses on any harness that cannot back it. The same bluff ships in Intent's own Coordinator, which asserts "you have no file editing tools" where nothing is removed.

found by studying Agent Orchestrator

The role file would have made worktrees undeletable

Writing the role to AGENTS.md worked — both CLIs read it. But an untracked file makes git worktree remove refuse, and that is the exact command run-role prints for you. The tool would have sabotaged its own instructions.

Every CLI takes the role by flag instead, so nothing is written into the workspace.

found by the user, looking at the screen

A failed run rendered in the success colour

The flow card chose its highlighted stage by position and always painted it celadon. A run that failed appeared inside a green card reading "Last run failed". A glance said pass.

It survived the agent's verification, my review, and 61 tests — because every one checked that the data was right, and the data was right. Only the colour lied. The suite has no way to see colour.

found by the user, from a stale card

The codex harness was dead, and every run was titled "## Task"

--ask-for-approval is a top-level codex flag; codex exec rejects it outright. Added while enabling auto mode, never re-tested, so the harness had been broken since. A verification wave died in two seconds.

Separately, run titles came from the brief's first line — which in any well-formed brief is a markdown heading. The registry filled with runs called ## Task.

found by an agent, in my test suite

Fifteen guard tests passed vacuously

Tests run inside a delegated harness inherit ORCHESTRATOR_DELEGATE, and the guard exempts on it. So fifteen checks asserting denial were asserting it from a context that is deliberately never denied. The agent's first full run came back 73 passed, 15 failed and it reported the diagnosis rather than just making the number green.

Six more, briefly

Three cwd-relative resolution bugs. agent-bus stop found the server through a file relative to the current directory, so a bus started elsewhere was invisible while its port stayed held. The dashboard was resolved from abspath(__file__), which points beside the symlink rather than beside the plugin, so the documented way to start the bus served a placeholder. And the doctor shelled out to claude mcp list, which is cwd-scoped, so it told you to run a command you had already run.

The orchestrator could never commit, even when asked, because the guard blocked all mutating git. Now ORCHESTRATOR_COMMIT=1 makes the authorisation visible in the transcript rather than hidden in a config flag.

/status took 6.2 seconds, shelling out to the doctor on every request. Cached to 12ms with an instant path.

The offline banner invented a timestamp. A failed request set the "last seen" clock, so a cold start with no bus claimed "the last response received, 10 seconds ago" over empty sections.

The dashboard hardcoded its own port in three places including its API base. Setting the documented AGENT_BUS_PORT loaded the page from one port while it called another — permanently offline against a healthy bus.

Two plugins failed to load because their manifest named hooks/hooks.json, which is auto-loaded already. Ours, and pi-plugin-cc — fixed upstream in a PR.

What two prior implementations taught

Two teams had built this before. Reading their source was the cheapest research available, and each caught a bug about to ship.

Agent Orchestrator

Its adapter layer renders the system prompt to both a string and a file every launch and lets each harness pick — six distinct injection families across 26 adapters. That is where the flag-based approach came from, and with it the discovery that the workspace file would break worktree cleanup. Its capability model is a fail-closed table validated when a binding is written rather than at launch, which is the shape the read-only refusal now takes.

Intent by Augment

Its specialists carry a roleReminder pinned last in the system prompt as non-truncatable, and re-emitted on every user turn — explicitly to fight attention decay. Single-shot invocations have no turns to hook, but the recency half transfers, and each role now carries one appended to the end of both the role and the brief. Both prior implementations converged on this independently, which is the strongest signal either of them offered.

What was deliberately not copied: their daemons, SQLite, CDC, SSE and desktop shells. That machinery exists to serve a GUI and a phone. A single developer with a local bus needs none of it.

Install

/plugin marketplace add maplenk/claude-orchestrator
/plugin install orchestrator@orchestrator-marketplace
/config → Output style → Orchestrator

Nothing activates until the output style is selected — the guard, the workflow and the harness prompt are all inert otherwise. A SessionStart hook links five tools onto ~/.claude/bin and starts the bus on 127.0.0.1:8477, which also serves the dashboard.

orchestrator-doctor                     # 20 checks, each with its fix
run-role developer --harness grok -- "<brief>"
run-role verifier  --harness codex --worktree -- "<brief>"
tests/run-tests                         # 88 checks

Installing from a local path copies the repo into the plugin cache, and /reload-plugins will not re-copy while the version is unchanged. Bump the version or rsync the cache — otherwise you are running an older build than the one you are editing.

Open

Independent verification is still in flight on codex, against the spec's acceptance criteria. It is the last wave and the one that matters most, because grok wrote every line of the dashboard and cannot neutrally review it.

Two states have never been rendered. The enso's failure variant and the flow card's blocked variant exist in code and resolve their tokens, but neither has been produced on screen. That is the same class of risk as the fifteen vacuous tests — a branch that has never fired is only probably wired.

The role is not re-injected on resume. A system prompt lives in flags, not in the transcript, so a resumed session would silently lose its role. There is no resume yet; this becomes a bug the day there is.

Role bodies are not content-addressed. Editing agents/verifier.md mid-flight changes what a running task is being judged by. Agent Orchestrator pins a digest per session and replays from it.

Built in one evening across claude, codex, grok and pi. The dashboard renders its own orchestration — the traffic feed shows the agents that wrote it, reporting as they worked. Roles adapted from the specialist model in Agent Orchestrator and Intent, rebuilt on Claude Code primitives.
